## 费用到底是什么

`policy_charged_runtime_s`来自历史审计映射的调用费用：每次调用汇总全部映射attempt的墙钟时间，同动作重复调用取完整费用算术平均。依据 `contracts/runtime_action_cost_aggregation_v1.json`、`contracts/runtime_training_package_v2.json`，以及 `src/data/build_runtime_training_package_v2.py` 的映射代码，不选择fastest-success、不丢失败/重试，不用ATE cycles或CPU time代替墙钟费用。

这项核对是来源合同及代码事实，不是本次重新审计原始attempt日志。正式集合的最终候选均为SUCCESS+D95可行，不能据此估计失败候选率。历史汇总可能包含失败/重试attempt成本，与最终候选状态是不同粒度。

runtime-policy-v1允许会话内H/HM前缀复用，v2没有更改该规则；本次outcomes没有顺序、restore/materialization等增量成本。`primary_online_cost_replay=false`：不把静态费用简单相加冒充真实在线累计耗时，不声称已测得ATPG提速。部署时如何判断已进入未知全局oracle的ε邻域也仍需单独解决。
