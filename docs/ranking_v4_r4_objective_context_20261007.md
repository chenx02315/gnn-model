# 排序目标与电路差异信息检查（2026-10-07）

## 结论：先修目标对齐，再评估上下文，不能原样重跑

检查只使用已封存的 TRAIN 聚合证据、本地原始小型诊断和历史源码。没有访问 A/B、BLIND、VALIDATION，没有加载权重、重做推理或训练。五份实际执行源码 SHA 与原 r4 审核锚点一致；18 权重映射沿用上轮已验证的历史承诺。

已验证：困难家族的正例没有因配对上限被漏掉；损失方向没反、家族大小没有直接决定损失总权重。真正的设计缺口是：平均配对排序不直接保证前10命中，也没有表达命中前 ATPG 成本；r4 没有图上下文。尚未证明这些缺口就是失败的因果原因。

## 1. 困难电路的排序目标

“正例”仍严格指 cycles 不超过该家族最小已测 cycles 的101/100；这是组合质量目标，不是 ATPG 运行秒数。D95 安全条件不变，K=10、三个 seed 不变。

| 家族 | 近优正例/动作 | 正负配对数 | 4096上限是否截断 |
|---|---:|---:|---|
| s13207 | 2/295（0.68%） | 586 | 否 |
| s15850 | 2/276（0.72%） | 548 | 否 |
| s35932（可穷举） | 1/10 | 9 | 否 |
| s38417 | 2/39 | 74 | 否 |
| aes_core | 6/350 | 2064 | 否 |
| spi | 1/736 | 735 | 否 |

每个拟合折有五个家族，每家族先取自身 pair loss 的均值，再等权平均（每家族20%）。所以“大电路的负例很多”不等于“大电路占据更多总损失”；稀缺正例也并未从训练配对中消失。所有实际正负配对都被使用。

但每个正例面对的大量容易负例也会稀释少数前排难负例的平均贡献；这只是目标性质，不能单凭它证明 r4 的梯度路径。每家族等权也不保证各家族都拟合好，共享网络仍可能在家族之间折中。

### 可复算反例：loss下降，前10反而失败

合成一个正例、100个负例，仅计算分数，不拟合任何模型：

| 分数构造 | 正例排名 | 前10命中 | 平均 pair softplus |
|---|---:|---:|---:|
| 正例0，所有负例-1 | 1 | 是 | 0.313262 |
| 正例0，10个负例0.01，其余90个负例-10 | 11 | 否 | 0.069857 |

第二种损失更小，却把唯一正例排到第11。它证明“平均pair loss更低”不保证你的推荐目标更好，不证明真实 r4 恰好经历了这条训练路径。

实际旧模型中，s13207首个正例排名21–74、s15850为2–70；这一目标未达到。pair accuracy、平均margin、平均loss都只能辅助解释，不能替代各家族首次近优命中排名。原训练未保存逐轮loss，不能判定收敛。

### 与论文核心成本目标的第二层偏离

实际 `torch_pairwise_loss(scores,index,pairs,torch)` 没有 runtime 参数；配对只看 cycles 是否近优，不包含 ATPG wall time。runtime 只在排序封存后的 replay 里累计。因此当前r4是“近优组合质量排序器”，不是已经训练好的“累计ATPG时间最小化器”。训练的120轮耗时不是ATPG耗时。

这不意味着必须直接把runtime当更优标签：成本只能使用合法的 fitting attempt/policy runtime，并保留失败/重试计费；不能用cycles、CPU time代替，也不能看到留出/BLIND成本再选策略。

## 2. 模型得到的电路差异信息

实际 real worker 调用 `fit_neural(torch,np,prepared,seed)`，没有传 graphs 或 uid_graph_keys，默认进入 CandidateMLP，而非 GraphSAGE。仓库有 graph ranker 实现，不代表 r4 使用了它。

| 输入 | 当前提供的信息 | 没有提供的信息 |
|---|---|---|
| HF/HMF两列 | 方案类别 | 电路内部结构 |
| H/M limit 的 log | 绝对动作设置尺度 | 设置改变后的故障响应 |
| H/M 相对最大值 | 相对动作位置；与绝对值结合可间接体现最大设置尺度 | 拓扑/扫描路径/故障分布 |
| common fault count 的 log | 电路规模/共同故障数量代理，同一家族内恒定 | 故障在哪里、受哪些结构影响 |

不能说“完全没有电路信息”：绝对/相对H/M结合能间接透露电路最大设置尺度，共同故障数也能条件化网络。也不能说“有7列，所以足够迁移”：这些尺度代理不等于拓扑或可测性响应。

上轮结果中aes_core共同故障数外推较大，spi较小；s13207/s15850/s38417逐列都在拟合范围内仍失败。单列范围内不等于联合分布相同，不能靠重新归一化解释全部问题。无精确特征碰撞也不证明特征充分。

**当前只能确认结构信息未供应，不能确认已有图特征能帮助迁移。** 不读取新图、不训练图模型，就无法证明候选响应相关性或架构收益；不能提前保证GraphSAGE有效。电路ID不应作为替代结构信息的捷径，留一家族时未见ID没有泛化依据。

## 3. 收敛后的下一方案清单（设计，不是训练放行）

1. 固定这次诊断和旧r4作为负结果基线，不改历史权重/冻结结果、不增加K、不放宽ε、不挑seed。首先记录各家族首次正例排名、前排负例数量、近优hit和top10 regret，而不是只看平均loss。
2. 实现候选的头部敏感排序目标与日志接口时，先用人工分数验证：降低目标是否确实推动至少一个近优动作进入前10；检查极稀缺正例、分数并列、全正/全负拒绝、家族等权、无held标签。目标可同时要求普通配对约束，但不要直接声称改目标就能治好真实模型。
3. 未来只做一个组件变更的受控比较：先保持同一7列与资源预算，验证拟合内困难家族是否改善；另一独立对照才增加已核验、outcome-free电路上下文。不要同时改目标、特征、epochs、数据量后无法定位收益。
4. 上下文候选先从已有TRAIN图的来源、UID连接、量纲与规模敏感性验证开始；描述符或GraphSAGE均属待比较选项。没有先验模型效果保证，不批量补电路。未证明上下文有效前不发布迁移成功结论。
5. 在质量hit可靠后再单独评估成本感知排序：固定ε命中门槛，再比较命中前累计policy ATPG wall time，保留未命中计费并分别报告。不得因未命中但尝试便宜而宣称加速。
6. 新真实训练必须另有冻结合同和放行，保持单worker、现有内存上限、零自动重试；BLIND与新增Tessent测量仍不放行。本次没有实现或执行新训练器。
