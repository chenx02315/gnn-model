# 下一节点：TRAIN 目标与费用关系诊断（尚未读取真实标签）

## 要回答的问题

核心目标保持：固定H64/M16/F4和D95安全前提下，尽量减少找到第一个epsilon近优组合之前的累计Tessent ATPG墙钟费用。cycles近优是命中条件，不是耗时；Hit@10只是一个排名指标，不能替代累计费用。

本轮已完成特征支持检查与源码/合成目标反例。下一步不直接更换模型或重跑训练，而是检查真实TRAIN上“什么组合近优、获取这些组合要付什么费用、不同家族方向是否不同”。

定义保持明确：近优oracle仍是家族内全部正式HF/HMF动作的共同最小cycles，不因分方案报告改成方案各自oracle；累计首次命中费用包含执行该首个命中动作本身以及此前策略应计的失败/重试成本。仅在既有费用策略与顺序关系核清后才允许费用重放。

## 权限门

当前feature-only授权不包含新标签读取。本文件是计划，不是授权或PASS证明。下一实际节点需要明确授权：只读既有固定六家族TRAIN包中的features、fit_outcomes、heldout_outcomes及其receipt/manifest，用于聚合诊断；不读BLIND/VALIDATION/PILOT、不读checkpoint或图原文、不训练、不调参、不提交LSF/Tessent、不扩充电路。

每个唯一动作只计一次，避免六折重复；若必须读取重复投影，只作一致性检查。保持原内存上限、单worker、零自动重试、SHA验证、唯一连接和新目录证据。

## 执行清单

1. 固定合同和外部SHA：列出字段、来源包、读文件白名单、1706唯一动作/6家族、所有拒绝项和输出上限。独立复核合成正反例后才读真实标签。
2. 核对费用含义：`policy_charged_runtime_s`是既有冻结策略下的费用标签，不未经核对就称作新测的端到端wall time。查阅既有策略/恢复合同，不访问原始大批日志，不用cycles、pattern或CPU time代替耗时；不插补、不取fastest-success，不忽略失败成本。
3. 聚合正例结构：按家族和HF/HMF记录正例/负例数量、比例及保证命中条件，沿用整数epsilon 101/100，不选更容易的epsilon/K。
4. 诊断标签关系：报告cycles相对家族oracle与策略费用的秩关系、并列处理和正例费用分布。只做描述性诊断；相关不等于因果，不混合不同家族的原始尺度。
5. 检查真实排序方向：在共同可比的方案/相对限额网格上检查家族响应是否一致，明确缺少可比候选的数量。无唯一/合理连接就标记缺口，不硬做插值或把最近邻当同一个动作。
6. 费用重放仅在前提核清后另列范围：若存在cache/prefix reuse导致费用依赖动作顺序，不能将静态候选费用简单相加宣称真实累计耗时；先保留这个阻断，不新跑ATPG。
7. 独立复核聚合结果与分母，封存小型指标和SHA，更新可读报告及Git版本。

## 诊断后才做的设计

根据结果冻结最小消融，不事后挑电路/seed：候选七列基线、家族等权normalizer对照、规模代理对照、预先定义的逻辑结构摘要对照。候选normalizer权重与家族loss权重分别控制。GraphSAGE是否必要要由对应消融回答，不能预先宣布有效。

目标设计要同时区分近优命中概率和费用预测；概率/费用比仅在费用与顺序无关等假设下作为待验证的简单基线，不宣称普遍最优。新训练、特征提取和远端环境变化仍需对应合同/授权/独立复核，本计划不自动开放。
