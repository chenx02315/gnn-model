# 从来源核验走向可训练数据：剩余两类证据

更新：2026-10-20。范围为六个 TRAIN 电路；不读取 BLIND，不重跑训练，不新提交 Tessent/LSF。

## 为什么现在还不能直接训练

例如，同一 H 配置在两个历史版本都出现过。E54–E56 已证明正式数据来自其中哪份文件，但不能据此认定另一个版本的运行从未发生，也不能把另一个版本的失败、重试或共享 H 前缀费用直接删掉。论文要优化真实累计 ATPG 时间，必须先说明一次推荐到底会付出哪些运行费用。

另一个例子：先删掉没有 PASS 的候选，再从剩余候选推荐，虽然表里不再有 PASS 字段，候选集合本身仍受结果影响。这样的历史回放不能自动代表运行前就能使用的搜索方法。

## 已核对的仓库源码事实

1. `src/data/build_formal_candidate_space_v2.py` 的 `normalized_row` 按 `result_status == PASS` 设置 `eligible_regression`；`src/data/build_candidate_space.py` 的 `build` 跳过 eligible 非 1 的行。这是事后候选集合，不足以证明运行前完整冻结。
2. `src/data/build_attempt_manifest.py` 的 `build_rows` 由电路、stage、log 路径、log SHA 和行索引生成 attempt ID；retry_index 使用稳定路径排序。它便于事后对账，但本身不是调度器提交时记录的重试顺序或独立物理调用证明。
3. 仓库内已检查的正式候选聚合、attempt manifest 构建、runtime mapping 和 timing recovery 代码，均不是原始 ATPG 网格/细化调度器。未在这些已检查源码中找到可认证的运行前 freeze ACK。不能据此宣称整个 A/B 或历史档案都没有。

## 后续导出的最小字段（设计要求，尚未要求或执行导出）

调用清单需要 source 文件原 SHA、原逻辑行/候选标识、电路/stage/mode/H/M 配置、原始 launch/job/task/session 标识、父/root 标识、事件顺序与 retry ordinal、是否计划/启动/终止的生命周期元数据，以及结果/log artifact 的记录路径和 SHA。保留共享调用的多对多引用，不把一个 source UID 当成一次独立调用。此阶段不要求导出耗时数值或质量结果。

全集证据需要独立生成器 SHA、配置/grid/seed、细化决策及输入来源、生成顺序/键规则、实际 roster SHA/数量和可信策略 freeze ACK。固定候选策略可冻结完整 roster；自适应策略则应冻结合法动作域的约束/生成规则、预算和缓存口径，并保留每次决策所见的过去信息和父子谱系。端点依赖的具体域数值可以在获准端点结果到达后按冻结规则生成。测量文件行完整、已冻结的自适应策略和固定候选全集是不同的证据，不得混为一谈。

若既有历史证据最终无法恢复，必须明确记录“不能支持什么结论”，再选择受限历史回放或重新预注册的小规模前瞻实验；不能把缺失证据插补为通过，也不立即批量增加电路或原样重跑训练。
