# E35：映射引用与计费口径对账

## 结论先说

本次已完成授权范围内的两项真实只读检查，并经独立结果复核：

1. **E34发现的7个跨阶段group，在当前映射快照中全部没有候选引用。** 其14条session均有“范围外阶段”排除记录，不应为了满足同stage假设而拆组、补边或自动加进候选费用。这里没有证明它们物理上没有调用归属。
2. **3次失败的排除记录也已逐条连上。** 10.060、10.580、7.770秒合计28.410秒，均标记为范围外阶段，stage/mode匹配，且不属于旧mapper声明的三个正式阶段枚举。因此不能直接称为正式候选已证实漏账，更不能把这些费用强塞入正式动作。
3. **提供集合内的引用账目可对齐，但只认证元数据及算术。** 全25,437条TRAIN session被完整分成已映射和已排除两部分，重叠0、未解释0。source是否等于真实独立调用、候选全集是否完整、排除策略是否合理，以及是否代表线上增量ATPG耗时，均未认证。

本阶段没有读取质量数值、ACTION_FIELDS质量相关列、BLIND、validation runtime表或原始日志；没有A/B数据端调用或写入、模型、optimizer、训练或LSF/Tessent。只读混合映射元数据时，validation行在费用/分组计算前被过滤。代码与小型记录按既有授权正常同步Git，不属于A/B实验数据写入。

## 目的、固定范围与执行路径

研究主目标仍是固定H64/M16/F4，在D95安全动作中更快命中ε近优组合。此处先保证“准备给模型的时间到底是什么”，不是再换模型或增加电路。

本次分析粒度明确区分：

- session：原始运行会话，保持原attempt/parent/group ID。
- source→session引用：旧映射表记录的引用；不能仅因名称带source就当成已认证的独立调用。
- action：按现有映射观察到的候选动作；重复source全部保留，费用代理取全部source算术均值，不取最快成功的一次。

输入固定为E34已核验版本的六TRAIN manifest/lineage共12表，以及旧r5的edges/exclusions两张混合元数据表。14文件共29,711,361字节，本地SHA全部吻合；这是缓存快照复核，不是新的A端现场认证。六TRAIN为aes_core、s13207、s15850、s35932、s38417、spi。

混合edges有26,512行，保留TRAIN 18,635行、过滤validation 7,877行；混合exclusions有8,947行，保留TRAIN 8,046行、过滤validation 901行。没有读取validation manifest或对其做费用分析。旧mapper会读measurement/result_status，故没有运行它。

执行顺序为：冻结合同与字段 → 合成测试 → 独立读取边界复核 → 一次14文件映射审计 → 独立摘要复核 → 针对3次失败的新聚焦两文件检查 → 独立结果复核 → 总览、SHA及版本同步。不是对成功r1反复重跑，也不是补跑ATPG。

## 为什么不能把几种秒数混着用

例如，同一份H前缀运行被多个候选引用，每个候选的历史独立尝试费用代理可以引用它，但把这些候选费用相加，不等于机器又物理执行了这么多次H。反过来，去重后的session总和也不自动等于每次线上选择所需的增量时间。

本数据中有245条session被多个source/action引用，形成1244条额外引用边：18,635条TRAIN边引用17,391条不同session。

| 口径 | 声明秒数 | 能解释什么，不能解释什么 |
| --- | ---: | --- |
| 全提供session各计一次 | 252070.420 | 包含历史排除工作；不是线上一次搜索工期 |
| 已映射session各计一次 | 160758.330 | 仅当前映射引用到的不同session之和；不是每候选增量时间 |
| 每条source引用各收费 | 176806.570 | 历史引用费用代理；不是物理新增运行时间 |
| 每action全部已观察source均值之和 | 169558.330 | 动作均值向量的汇总；不是机器总耗时或加速比 |

引用费用比mapped unique多16,048.240秒（相对多9.98%），这里是**计账口径差异**，不是实测线上开销增加。费用向量全部实际计算并封存规范SHA；没有选最快、丢失败或按费用挑示例。

已观察1780个source标识、1706个action：1632个action各1个source，74个各2个source。均值只覆盖这些已观察引用，不能反推全部历史调用完整。

## 验证、限制与复盘入口

按既有约定，Markdown总览是主要产物，不另建仪表盘。附[复算Notebook](../notebooks/E35_mapping_metadata_checks.ipynb)，4个代码单元已用标准Python按顺序执行通过，包含输出；本机缺nbformat/nbclient/ipykernel，**未做Jupyter内核执行或nbformat库验证**。Notebook内给出已有Jupyter环境下的精确执行命令；它只读两个小摘要，不重新扫描源表。原始代码与测试在scripts/tests中可独立检查。

## 下一步如何收敛

1. 不再把这7组当作必须修补的正式费用缺口，不重复E34/E35原样审计；也不据此加电路或补跑Tessent。
2. 先确定论文采用“历史独立尝试费用代理”还是要主张“线上增量ATPG时间”。两者不能偷换。前者可用本次观察到的引用/重复均值口径；仍须补完整候选/source全集与产生时点证据，不能由edges反推完备性。
3. 再做生产数据适配、候选/特征冻结与安全质量连接；任何质量数值读取须按下一整阶段权限和held-out冻结规则进行，不能把本次“混合元数据审计授权”当成质量读取或训练许可。当前E30训练放行门未改变。

本阶段得到的是明确的元数据对账结果及费用口径，不是GNN泛化改善、ATPG加速或正式TRAIN完成。
