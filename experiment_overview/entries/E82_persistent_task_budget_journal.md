# E82：阶段额度先落盘，再交出任务 token

## 目的与实际推进

核心研究目标不变：在 D95 安全约束下减少找到近优组合前的累计真实 ATPG 时间。E81 的额度只在内存里，重新创建对象就会清零；因此还不能用于任何实际调用。E82 补的是本地文件扣账与确认协议，不是新一轮训练或 ATPG 性能实验。

例如，一个 H/M/F 配方包含 3 个 Tessent 槽和 2 个翻译槽。必须先把本槽消耗的额度写入固定账本并收到本地 fsync 成功确认，才返回 token；失败不退额度。上一槽的结算没有确认，下一槽不能继续。

## 实现范围

- 保留 E81 内存原型，新增独占创建的 v2 文件账本，头部绑定完整计划和次数/时间上限。
- 每次扣账与结算使用有界、规范 JSON 哈希链；写入、同步或文件身份检查不确定时封闭写入口。
- 不提供重开写入或重启自动续跑；既有固定账本不能覆盖，新任务 ID 不能复用原槽。
- 只读回放检查结构和额度变化，不能证明历史 fsync 曾成功，也不授予执行权限。
- 串联 E81 的固定合成配方，不打开真实报告、模型、标签或远端文件。

## 验证记录

初版草稿没有被接受：发现建账输入别名、关闭异常及 Windows 时间戳兼容问题；第一冻结版虽然通过 13 项测试，独立反例又证明回调重入后可能在 writer 已失效时返回 token。旧摘要与回归日志保留，不用它们代替修后验证。最终版补 busy 屏障、写后可用性检查，以及只读打开前的普通文件检查和非阻塞标志，防止 FIFO 打开悬挂。

最终验收：`PASS_LOCAL_SYNTHETIC_FILE_PROTOCOL_ONLY`。父代理专项 15/15 通过（0.117 秒），独立复核 15/15 通过（0.124 秒），并独立重验扣账/结算两类重入反例。完整回归 1,185 项：1,179 通过、6 条件跳过、零失败/错误，70.756 秒。完整回归含旧模块微型本地子进程测试；E82 新增模块/测试/串联不启动子进程。

两次摘要和 Git 收录副本均为 9,984 B，SHA-256 为 `1ef4e29dce91d24a5d7144fa05de3f6abd24a1c16f379c600f7c96b3c398a2ed`。两个原始账本均为 8,211 B、11 行（头部加 10 个事件），SHA-256 为 `89a608baf13dbf4e7f859744af3419870bd3145695f6b86f696e486ef95d7150`。独立复核核对了规范编码、哈希链、完整计划/上限、3+2 槽、60 ns 声明包络及 23 ns 合成结算数。

最终证据索引为 `data/manifests/ranking_v6_e82_validation_20261022_r3.json`；其中记录代码与测试、原始日志和摘要的实际 SHA-256。只读回放不输出可用耗时或历史 ACK，不能把完整字节误当作当时确认成功。

## 边界与下一步

“固定路径”由调用方可信阶段命名空间保证。本库不能阻止调用方换一个任意目录建立另一套额度；因此不声称全局防清零。Windows 本地 fsync 成功不是断电、目录项持久性、Linux 文件系统或恶意同用户竞争安全证明。

23 ns 仍是 E81 合成算例的约定数字，不是实测 ATPG 时间。新增模块不启动进程、不读取真实数据，不构成生产资源守卫、训练或作业放行。

下一真正依赖是把额度账本与进程生命周期账本绑定到同一阶段身份，先本地验证双账本 ACK 失败窗口；之后仍需真实输入/资源白名单、翻译产物身份及完整有界执行包，不能原样重训。
