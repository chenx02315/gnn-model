# E79：把下一轮实验收敛为四块可验收工作

日期：2026-10-22。本轮仅做本地源码/小回执核对、预算计算器和测试；没有新增远端访问、容器、ATPG、训练或真实标签读取。

## 先说结论

下一步不是重跑模型，也不是继续重复 E78 的 Python 场景。应先让 **aes_core/spi 的真实输入、运行前候选、Tessent 适配和完整费用预算** 能够彼此对应，再开始小规模真实采集。

E78 已解决“固定 Linux 进程与持久账本可以一起工作”。它没有自动提供网表/故障正文身份、整数端点、真实模型兼容性或 Tessent 的资源上限。本轮保留 E67 原始 18 个待填字段，不用模拟通过把它们机械填满；将其归并成下面四块，避免一项一项零散推进。

## 具体清单及顺序

| 工作块 | 已有证据 | 尚需取得的产物 | 验收后才能做什么 |
| --- | --- | --- | --- |
| 1. 输入身份 | E70 当前 driver/Tcl/config 字节；共同故障 manifest 声明 | 可执行程序、库/网表、故障正文/映射、图及使用模型时的 checkpoint/特征版本身份 | 确定唯一输入白名单，不以路径或 manifest 声明代替正文认证 |
| 2. 运行前候选与模型输入 | E68 符号模板；E71 请求 H/M 与实际产出分开 | full-H、每个 H 后的 conditional-M 端点及全部采集费用；整数清单/别名/全域分母；旧模型兼容证明或新版本设计 | 固定三类策略对同一清单的排列，不使用未来实测数补模型输入 |
| 3. Tessent 适配与资源 | E78 固定 Python 后端和账本联跑 | 每个 Tessent 调用的请求/返回、身份、清理与计时接口；真实内存/timeout/license/线程/磁盘限制 | 在合成验证和独立复核后形成真正的有界采集入口 |
| 4. 完整预算与公平比较 | 已定位 F 的多次探测路径；本轮预算器 | 真实 F 上界、端点/额外调用上限、候选数、session/seed 清单、固定顺序及预注册 | 连同失败、确认和端点成本，冻结一个完整执行包，届时一次整体放行 |

先做第 1/2 块的身份与语义绑定；第 3 块接口和第 4 块预算可以并行本地准备。真实 ATPG 之前必须合并成一个完整包，不能单独拿“代码通过”或“数字填齐”当执行许可。

### 最重要的模型输入决定

“请求最多 3 条 H pattern”与“实际报告产出 3 条”不是同一件事。旧模型特征链使用后者；新动作在运行前只能知道前者。现有证据不足以证明恒等，也不足以认证某个 checkpoint 能直接接受新请求。

因此不把请求值偷偷塞进旧模型。下一本地实现应明确分离请求、实际观察和质量结果，并设两条显式路径：有证据证明兼容才复用旧输入；否则另立运行前可知的请求/结构特征版本，重新冻结模型接口。后一条不是本轮重训授权。

新候选也不能因为来自模板就宣称预先 D95 安全。若以后采用 F 补足策略，必须在接受结果前实际核验 D95；不可行、超时和失败都保留并计费。不能据此绕过旧模型的 safe-only 准入合同。

## 本轮实际实现的预算器

新纯函数 `src/data/prospective_pilot_budget_v1.py` 不读文件、不启动进程。它只按明确提供的上限做条件计算，所有返回结果始终 `execution_ready=false`、`training_release=false`。

对已经检查过的旧 F 搜索结构，若 full-F pattern 的可靠正整数上界是 U，则保守计入：一次覆盖率探测、可能的一次 full-F 回退、至多 U 次整数修正、至多 ceil(log2 U) 次二分探测。F−1 是已有低端点或进入 F 前的 F=0 状态，不凭空再免费产生一次结果；若新流程另加确认调用，必须另外收费。

为避免把 H/M 前缀当免费，初始设计按每次 F 探测都重建 H/M 的保守 HMF 包络计数。其他端点标定、额外检查或调用仍须显式提供上限；预算器不声称覆盖旧完整 driver 的所有分支或未来未知子进程。

举一个**纯算术例子，不是真实实验参数**：U=4、每 session 最多 2 个候选、3 个 session，每 session 另有 5 次端点调用和 7 次额外调用。每个候选最多 8 次 F 调用；包含每次重建 H/M 和初始前缀，共 26 次。于是每 session 是 5+7+2×26=64 次，3 个 session 共 192 次。若每次允许 10 秒加 2 秒清理，时限之和是 2,304 秒。

这个 2,304 秒既不是实测耗时，也不是端到端预计完成时间；排队、准备、未覆盖的 license/调度/IO 和 session 开销不能被省略。未来需要同时保留逐 attempt 观察区间和完整 session 时钟，不能把 ATE cycles 当时间。

### 对当前真实小试点的输出

aes_core/spi 的真实 U、候选数、端点/额外调用上限、session 数、真实 timeout/清理上限仍为空；预算器对两电路均返回 `INCOMPLETE_DESIGN`，总次数和时限保持空值。它不会以 924 个符号模板、历史 PASS 行数、128 MiB 的 Python sandbox 或旧训练资源来填空。

新准备脚本只读取固定 10 份本地代码/合同/小回执（单份不超过 64 KiB），核对参考 driver SHA、E70 未认证 checkpoint 状态及 E78 仅固定 Linux 通过的边界。两次输出摘要逐字节一致；示例与真实缺项在 JSON 中分栏保存。

未来真实入口还必须在每次启动前持久扣减对应调用额度；用完额度应记录“预算耗尽/未观察完成”，不能改记为 D95 不可行，更不能免费补最后一次 F。预先规划的低覆盖率探测是搜索动作，不等于失败后自动重试；零自动重试不意味着这些动作可以不收费。未知清理、写入确认或耗时必须阻断后续调用。当前旧 driver 的 `-license_wait 5` 也不是整次 attempt 的 wall timeout。

## 测试与独立复核

本轮新增 11 项测试（预算器 7、准备器 4），与 5 项既有 pilot 准备测试合计 16 项针对性测试通过，0.059 秒；独立复核另执行同组 16 项通过，0.057 秒。完整相关回归 1,138 项，其中 1,132 项执行通过、6 项条件跳过，零失败/错误，43.878 秒。旧完整回归含微型本地 Python 子进程测试，不是新 ATPG 或远端实验。

两次准备输出与 Git 小结果均为 11,359 B，SHA-256 `1b0535baf9ac57d5f42008edcaa4da4a2b8e3c93913844de0142f4deb1f441c8`。独立复核检查全部 10 项输入字节哈希、参考搜索公式与回执边界，结论为 `PASS_LOCAL_CONVERGENCE_ONLY`。期间一次复核因额度限制中断，用户继续后恢复并实际完成；没有把中断记作通过，也没有为等待复核运行远端任务。
