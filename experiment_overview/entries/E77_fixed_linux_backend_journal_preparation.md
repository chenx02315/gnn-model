# E77：将固定 Linux 清理后端接入持久账本

日期：2026-10-22。当前结论：**代码接线与本地模拟验证已完成；新组合尚未在 Linux 实际联跑。** 不产生新的 ATPG 耗时、模型训练或加速结论。

## 为什么做这一步

核心目标仍是在 H64/M16/F4 和 D95 安全条件下，减少找到近优组合前累计消耗的真实 ATPG 时间。为此，必须先保证每次调用都有可追溯记录，失败和清理时间不能漏计。

E75 已实际验证固定 Linux 子进程清理；E76 已模拟验证持久账本协议。两者分别通过不等于组合通过。E77 新增独立 v3 后端，让真实代码路径调用已审查的固定载荷、内核前置检查和进程组清理函数，同时保留原 v2 和原始证据。

## 已实现的约束

- 仅固定三项，顺序为成功、失败、超时进程组；单 worker，零自动重试，没有任意命令或真实数据入口。
- 内核前置检查和子进程回收设置先于临时目录及启动；意图写入并确认后才允许启动。
- 身份记录包含主机、boot ID、PID、进程组和启动时刻；同一批必须属于同一主机与同一次系统启动。
- 已拿到句柄后，读取身份、确认写入或后续检查失败，都先清理已知进程组。无法确认启动结果时封锁后续项，不猜测成功。
- 只有固定三项按序完成、清理通过且实时写入确认齐全，才产生完整区间总和。完成第一项只是前缀完成。
- 即使第三项的终态字节已经完整写出，只要写入确认失败，也不能报告完整费用。重新读取文件不能倒推出当时确认成功。

例如：第二项已启动，但身份确认失败，不能把第一项的时间当作三项总费用；第二项必须清理，费用保持空值，也不能继续第三项。

## 验证证据的边界

本阶段所有新增 v3 场景均拦截子进程启动、内核检查和临时目录创建，使用模拟时钟；**新增 v3 实际子进程、远端会话、容器均为 0**。旧模块完整回归包含微型本地 Python 子进程测试，不能把整套回归描述为零操作系统进程。

八类小型案例覆盖正常三项、意图确认失败、未知启动结果、空句柄、身份读取失败、身份确认失败、清理失败、第三项终态确认失败。完整原始小账本和摘要位于 `data/manifests/ranking_v6_e77_demo_*`；源码 SHA、确定性比较和测试结果由 validation/review/publication 回执绑定。

中间版本及失败发现保留，不覆盖历史：早期版本只完成前缀即可报完整、可改变顺序、前置失败后可更换后端，以及缺少整批主机/boot 一致性屏障，均在独立复核后收紧。修前测试不作为最终验收结果。

最终针对性测试 18 项通过（0.241 秒，零失败/错误/跳过）；相关完整回归 1,114 项，其中 1,108 执行通过、6 个旧条件跳过，零失败/错误，耗时 115.250 秒。主机和 boot 变化的两种情况均在新增测试内验证：清理第二个已知句柄、费用为空、禁止第三次启动，重新计算合法日志哈希也不能绕过回放检查。独立复核核对源码和测试逻辑、小账本哈希/回放，而非把修前独立测试次数冒充修后执行次数。
