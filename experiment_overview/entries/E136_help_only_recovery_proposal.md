# E136整包提案：小型工具帮助代替整份PDF，随后只做一次F仿真

## 目的与失败原因边界

E135并未启动仿真：首读在参考手册的打开前大小检查处停止，确切尺寸没有返回。不能把它说成服务器登录失败、内存爆满、向量不存在，或已确认手册一定超过32MiB。旧STIL已有443378字节的hash-only回执，但没有正文或导入验证。

新方案不继续猜整份PDF的尺寸，也不提高512MiB采样阈值。改为先运行一个仅输出命令帮助的Tessent会话，获取小型、版本对应的用法信息；独立核验充分后，再运行另一个会话，只重放已有F向量做故障仿真。两次工具启动用途不同，均明确计费，不冒称只有一次Tessent启动。

## 计划清单

1. 本地完整实现、测试、冻结精确包并独立预审后，才启动新窗口。
2. 第一次A连接内：固定STIL/库/Fbasic/单F TSDB身份核验；3项Python进程自检；最多一次help-only工具会话。固定帮助目标仅help、read_patterns、simulate_patterns、report_patterns，不读设计/库/向量/故障，不仿真，不生成pattern，不打开GUI或manual viewer。手册只允许确切路径stat，不读取正文。
3. 将实际工具版本、帮助内容、来源身份和旧手册中的故障仿真说明一起独立复核。帮助过于简略、选项或语义不能确认时，不能放行F仿真。
4. 全部门禁通过后，第二次A连接内做3项新进程自检，再最多启动一次隔离F会话；保持baseline DI-only、无H/旧F状态合并，保存导入前、导入后仿真前、仿真后三份完整快照。完整重放既有向量，不调用create_patterns。
5. 第三次连接只导出固定结果；按canonical故障逐项合并E134 H集合与新F仿真检测集合，独立核对67656/71216门槛，封存真实成功/失败。不能把新仿真耗时当旧ATPG耗时，也不因此放行18动作或训练。

## 一次整体授权的边界

详见contracts/physical_f_replay_help_recovery_proposal_e136_v1.json：最多3个A连接，1次help-only加1次F仿真，单worker，512MiB进程树采样阈值，0新ATPG，首失败停止、零重试。首连接最多240秒、帮助会话60秒、F会话1800秒、整包从首次新连接起3600秒不续期；输出小型帮助日志，不传整份PDF。Linux进程自检最多6项，两个工具会话各3项。不用LSF、不访问B/BLIND、不训练、不改历史。

这是全新E136目录和时钟，不得复用已关闭E135的余连接或工具额度。没有新的明确整包授权前，不做任何E136远端调用。
