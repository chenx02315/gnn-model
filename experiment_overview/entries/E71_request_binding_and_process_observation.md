# E71：把运行前请求与运行后结果拆开，补齐进程观察验收

日期：2026-10-21。承接用户对下一节点的整体批准。本轮只有本地代码、既有 E70 小型投影与合成事件验证，没有新 SSH、Tessent、LSF、训练或真实标签读取。

## 这一步解决了什么

例如“请求最多 3 条 H pattern”，不等于“报告里实际产出了 3 条”。本地源码显示：driver 将请求放进 `PATTERN_LIMIT`；Tcl 把它交给 `set_atpg_limits -Pattern_count`；driver 另外从 `statistics.rpt` 的 `#test_patterns` 解析实际数量。没有保证两者恒等的断言。因此不能提前把未来实际数量填进模型输入，也不能简单把旧特征换成请求值就宣称兼容。

新实现把这条边界变成了测试，而不只留一段说明：

- 输入绑定器仅接受 aes_core/spi 的 HF/HMF 整数请求坐标，拒绝 `h_patterns/m_patterns`、D95、cycles、runtime 等结果列；M 请求绑定对应 H 前缀，HF 没有 M。
- 完整的调用方候选清单获得规范化 SHA 和 H/M 最大值；重排不改变身份，截成 top-k 会改变 SHA。函数不能凭空判断调用方是否隐瞒了候选，因此实际执行前还必须与预注册的全清单 SHA 对照。
- 显式保留 checkpoint、图、故障正文、可执行环境和资源策略等缺项。即使把所有 SHA 都填满，也不会放行执行或宣称字节已认证；不会输出可冒充旧模型输入的 feature vector。
- 进程观察检查器验证“计划→观察到启动→观察到回收”的顺序、host/boot/PID/启动 ticks 和可比单调时间。同一实体不能重复收费，未终止调用阻断后续启动；失败、超时、取消不被丢掉，缺失/不可信终止不会插补完整费用。

## 可复盘的小结果

准备脚本只读两份逐 SHA 固定的 E70 元数据投影，接出两电路的 driver/Tcl/config 身份。故障 manifest 的 SHA 没有被偷换成故障正文 SHA。

每电路仅使用人为构造的 HF(H=1) 与 HMF(H=1,M=1) 示例测试连线；它们不是由真实端点展开的正式整数清单，不计作新实测候选。每电路仍有 8 类身份待核实，实际请求/产出同义性、模型兼容、候选安全准入仍未认证。

进程观察使用手工整数时间戳，不启动子进程。即使事件结构完整，也只说明事件验证器接受了输入，不证明操作系统真的执行/终止了进程。记录的观察区间包含启动/回收观测开销，不能塞入旧 E65 的“独占原子 ATPG”费用字段，更不是完整在线搜索耗时。64 次/256 事件只是解析器上限，不是批准的真实作业预算。

## 验证与独立复核结果

新功能 20 项测试全部通过（0 跳过、0 失败、0 错误）；独立复核另行运行同一 20 项也通过。相关回归最终覆盖 97 个模块、956 项测试，950 项执行通过、6 条件跳过，0 失败/错误，71.759 秒。相关旧测试包含既有 tiny 本地合成子进程，不是 Tessent/LSF/训练。

首次回归入口没有把 `tests` 放入 Python 搜索路径，导致 E40/E41 三个旧模块的同级导入失败（67.888 秒、3 导入错误）；已保留原始失败日志。只更正本次测试启动入口后完整复跑，未改旧测试、未屏蔽报错、未重试任何真实实验。最终通过不是把首次失败删除后得到的结论。

小型准备结果、两次回归日志和独立复核回执在 `data/manifests/ranking_v6_e71_*`；准备 JSON 为 13,296 B，4 个合成观察的时间戳纯属构造，合计 40 ns 不是任何程序的真实耗时。

## 下一节点和停止边界

本轮本地实现、测试、独立复核、汇总封存和版本同步作为一个节点连续完成，不逐小步重新申请批准。

真正采集之前仍须形成一个完整执行包：已认证的可执行程序与库/网表/故障/图，真实整数候选与端点采集费用，冻结策略顺序，明确内存/timeout/磁盘/attempt 上限，以及 Linux 进程组回收和内存守卫的合成验证。真实 runner 还须持久记录启动与回收，并有版本化计时口径连接，不能把本轮纯函数当成已部署 runner。

这组依赖未满足前不原样重训、不扩大电路、不自动重读已耗尽的 E70 文件额度，不启动实际 ATPG。后续实际采集仍需一个具体且有界的整体执行包，不能用“继续”或旧 Job ID 冒充无限采集权限。
