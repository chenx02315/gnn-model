# E32：普通文件冻结与留出读取顺序的本机验证

## 目的与边界

E31 已补完内存中的切分、标准化、计费及连接。这里继续补文件边界：例如排序快照写的是模型 A，却意外读取模型 B 的字节，必须在接触留出结果之前拒绝，不能只凭“文件存在”就继续。

本轮仅在本机临时目录使用生成的字节和固定评分，不加载 PyTorch、不解析 checkpoint、不读取任何真实标签、不访问 A/B，也不训练。模型字节是明确写着“非 checkpoint”的占位串；callback 返回生成的探针标志，不是真实 outcome。实现和测试 PASS 不代表模型有效、真实 freeze 已放行或 ATPG 时间减少。

## 已补的路径

1. 根据可信主机配置选择临时父目录，纯词法检查通过后才进行文件系统操作。只创建前缀为 `gnn_v6_freeze_fixture_` 的全新直接子目录；既有目录不接管，`/ssd`、A 端路径、受保护路径、相对路径和路径穿越均拒绝。Windows 比较不区分大小写，POSIX 比较严格区分；不能拿 Windows 上的 POSIX 词法模拟当作 Linux 运行证据。
2. 只允许三项：`model.bin`（1 MiB）、`normalizer.json`（16 KiB）、`freeze.json`（256 KiB）。前两项是有界 opaque 字节，仅核验 SHA；文件名叫 JSON 不代表本模块认证了 fit-only 标准化语义。
3. 冻结快照绑定模型、标准化、特征快照、拟合 UID 的 SHA，以及留出家族、seed、全部 UID/评分和完整排序。拒绝重复 JSON key、额外字段、非有限评分、UID 重复/错序、排序不符和非规范字节；排序规则为分数降序、UID 升序打破平局。快照不含 cycles、费用或 outcome。
4. 用 `xb` 独占写入，flush/fsync 后有界读回、逐字节和 SHA 校验；全部完成才给本实例成功 ACK，且固定保存当次三份哈希。release 的 expected 三元组必须与原 ACK 完全相等，检查先于磁盘和 callback。失败文件保留，不覆盖、不自动重试，也不允许外部补齐半成品后冒充成功。这里没有跨进程恢复支持。
5. 读回检查普通目录/文件、软链接/reparse/hardlink、根目录身份、打开前后描述符身份和大小，且目录必须恰好三项。所有预期绑定及三份文件均核验后，才能检查并调用生成的 callback，每次合法 release 调用一次。

“每次调用一次”不是跨调用、跨进程的实验 once 许可；旧 E28/E29 once 没有触碰。默认 `implementation_only=False` 拒绝；该选项也不是来源探测器或授权真实数据读取的凭据。

## 测试与真实证据等级

专用文件测试 18 项，加 E31→E32 集成/合同 3 项，共 21 项：20 项实际通过，1 项因 Windows 缺少创建 symlink 的权限（WinError 1314）跳过。真实 hardlink 拒绝在本机已测；reparse 属性仅为合成元数据测试，不声称已做 junction 或 Linux 正向测试。

集成测试把 E31 五家族拟合的标准化字节、特征 SHA、拟合 UID SHA 接入本地冻结。正常三文件准确读回后 callback 为 1 次；错标准化字节或篡改模型文件时为 0 次。固定评分只是占位排序，不是新增模型前向或学习效果。

最终完整相关回归、独立复核及源码 SHA 见下方小型回执；独立重复的相同测试不再次累计覆盖数。

修复后的完整相关回归共 595 项：489 项执行，106 项条件跳过，零失败、零错误。分组为 v6 主测试 397 项（3 跳过）、门禁检查 16 项（0 跳过）、既有 stage/run/diagnostic 182 项（103 跳过）；新增 21 项已包含在总数中，不再相加。

## 首次审核发现与修复（保留负面证据）

首次版本 `c7ea1174...15b255` 的 19 项测试虽无失败，但独立复核发现：只记“persist 成功”的布尔值，没有记成功时的哈希。复核在纯临时目录中实测，先保存 A，再将三个文件完整替换成另一套合法 B，`release(expected B)` 仍调用 callback 一次。这证明测试通过没有覆盖到 ACK 与文件版本的绑定。

已聚焦修为不可变的三哈希 ACK；合法 B 整体替换也会在任何磁盘/loader 操作之前拒绝，A 正常路径仍通过。新增两项回归，修后源码为 `9ad2f48b...a4444`。这是未发布实现的本地缺陷修复，不是正式实验重试；旧实验 once、真实标签和远端都未触碰。原版字节已在本地 staging 的 `v6_file_freeze_20261016_r1/pre_fix_source.json` 保存为 base64，原字节 SHA 与审核版本完全吻合；Git 仅记录小型反例与修复回执。

## 没有被这一步解决的事

- 未认证真实模型/标准化/候选的来源，也未加载模型；文件 SHA 相同只证明字节相同。
- 未在真实生产根目录运行，未访问真实 held outcome。G06 获得的是本机 fixture 的实现与文件读回证据，不是生产放行。
- 信任本机临时目录层级和环境配置，不声称能抵御恶意并发目录替换，不是操作系统沙箱。只 fsync 文件，不保证跨平台断电后的目录项持久性。
- 真实原始 attempt 的调用、计时语义、共享前缀，真实输入/评分域以及生产 trainer 仍待接入；本轮不修改 E30 八项门的真实状态。

下一节点应将已完成的内存账本和文件边界用于真实 reader 适配设计，明确哪些旧字段能一一连接、哪些不能；再补模型域和受控 trainer。不能靠删失败、补耗时或重跑旧合成实验绕开真实证据缺口。
