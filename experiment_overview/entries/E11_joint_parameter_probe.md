# E11：模型参数空间的联合探针

## 最重要的结论

在现有 1,345 参数的七特征 MLP 中，8/8 个预先选定的临时参数提案，经真实 PyTorch 前向产生新分数后，都使合成未命中风险与标准化成本下降。所有模型恢复初始参数，没有保存 checkpoint、执行 optimizer 或启动训练。

这补上了 E10 的“分数字典变化”到“真实参数变化”这一小规模接线验证，但不证明持续拟合、跨电路泛化、D95 实测或真实 ATPG wall time 加速。

## 冻结设计与资源

- 两个 n6/K3 合成 fixture（mixed/rare），seed 11/29/47/83；每组独立32基线+32梯度采样。
- 既有工厂 `runtime_ranking_v3.make_candidate_ranker`，7→32→32→1，CPU float64。初始化由固定 case/seed SHA 派生。
- 合成七列特征由固定模板生成，不是生产数据预处理；不读取 checkpoint 或真实标签。合成环图只记作溯源，现有 MLP 不消费图结构。
- 使用实际基线前向分数计算受控目标梯度，再通过已验证 VJP 得到两个参数梯度。负梯度 L1 归一化后混合，λ={0,.25,.5,.75,1}、步长={.05,.1,.2}，每组15候选。
- 只按采样预测选择一个候选；八组完整协议、方向、选择、初始权重与特征哈希全部冻结后才开始精确验证。不用 oracle 挑选或拒绝后换候选。
- 每组最多验证基线和唯一提案两次原始 PL 精确枚举；验收 Δrisk≤1e-12 且 Δnormalized_cost≤−1e-8。B=K×max(cost) 前后固定，命中动作计费。
- 参数变化是真实模型写入并前向；finally 用 tensor equality、身份与权重 SHA 校验精确恢复，RNG也恢复。“接受”只是本次验证判定，不意味着留下权重。
- B 端已有固定 Docker 镜像，CPU/worker=1，cgroup内存1 GiB、额外swap=0、pids64、无网络、只读挂载、120秒超时。正式执行一次、零自动重试。

采样 namespace 是 `v6-synthetic-conditional-control-v1`；初始化/提案 namespace 是 `v6-synthetic-joint-parameter-e11-v1`，不混称同一随机派生协议。
