# E66：用本地小进程验证启动、超时、终止与记账

日期：2026-10-21。此记录仅针对本地固定 Python dummy，不是 ATPG 采集、模型实验或加速结果。

## 这一步解决什么

E65 验证了“给定事件能否正确记账”，但没有启动程序。E66 进一步检查：先把启动记录落盘，再启动一个很小的本地程序；程序正常退出、失败退出和超时后，是否都能按实际观察记录结束。

仅允许三个写死的程序：退出码 0、退出码 7、sleep 2 秒。没有任意命令入口，不读电路、候选、模型、checkpoint 或真实标签；没有 SSH、A/B、Tessent、LSF 或训练。

## 实现与停止条件

- PLAN 和 START 都完成 flush/fsync 后才允许启动一次子进程。任一写入失败，不启动。
- 单 worker，零自动重试；超时只执行一次 kill 和一次有界 wait，不把“发出 kill”当成终止证明。
- 启动前预置进程内禁止派发标记。只有已验证 wait/reap 且 END 落盘确认后才解除；异常、中断或不完整记录均保留禁止派发，即使换一个新账本也不能绕过。
- 这是保守停止，可能子进程已经结束仍被禁止继续；没有公开 reset，不提供跨进程恢复或通用进程树清理保证。
- 清理 handler 尚未建立时的中断，仅依靠全局禁止派发阻止后续启动；不保证该窗口内的子进程已经立即清理或回收。
- 成功、失败和超时的 D95、ATE cycles、输出产物 SHA 都保持 null，不捏造质量或成功 cache。
- E65 原实现不修改；实际 PID 只在回执中返回，START 的 PID 仍为空，不伪造持久进程身份绑定。

## 复核中修掉的问题

第一次修订补了 Popen 内部抛出 KeyboardInterrupt/SystemExit 的禁止派发路径。独立复核随后用全 fake 的一次性 trace 证明：Popen 返回后、清理 try 尚未接管时中断，仍存在窗口。该 fake 复现对应源码 SHA `121f4de2827d0c8c8999046e6089f2120a85b916b9739f57ed5a6322798dcc7c`，不是旧版本实际子进程实验。

升级独立架构审阅后采用“启动前预置、完整结束后解除”的最小修复，并增加该窗口回归。没有扩大到远端部署、持久进程监督或重试系统。

## 耗时口径与边界

本轮区间是本地 dummy 的“START 取时到实际回收后 END 取时”，包含 START 落盘、启动、等待及超时清理开销，不是纯子进程时间，更不是原子 ATPG wall time。E65 汇总字段名称沿用协议兼容格式，不能脱离 dummy 标记当作真实 runtime 标签。

实际本地时间、PID 和临时目录会变化，因此不要求两次字节一致，不把它与 E65 人工时钟演示的确定性混淆。没有宣称操作系统硬内存限额；仅执行无第三方依赖的三个极小程序，真实 ATPG 内存配置仍待核实。

## 验证结果

- 父代理针对性测试 45 项通过（adapter 14、冻结 E65 ledger 26、plan 5），零跳过/失败/错误，0.293 秒。
- 独立复核 adapter 14 项通过；另以优化模式验证 demo 的显式检查不会被 `-O` 移除，没有为该检查启动子进程。
- 全部相关回归 900 项：894 项执行通过、6 项条件跳过、零失败/错误，37.940 秒。回归日志中的 transport timeout JSON 是原有全 fake 负例，不是本轮 SSH。
- 独立复核通过后，在全新本地目录实际运行一次三程序集成：SUCCESS / FAILED / TIMEOUT 均正确结束，三个子进程都已回收；正常/失败退出码分别 0/7。重放汇总与现场汇总完全相等，三个区间之和 163,580,200 ns。

上述 0.164 秒左右仅是三个本地小程序的记录到回收区间之和，**不是 ATPG 性能、模型命中时间或加速比**。单元测试中的固定小程序会随测试套件执行；不把多次测试重复加成独立实验规模。
