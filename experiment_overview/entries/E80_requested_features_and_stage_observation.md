# E80：修复请求限额与实际产出混用的接口

日期：2026-10-22。承接用户“请你解决”。本轮实现代码并做合成验证，不读取真实 checkpoint/标签，不运行推理、ATPG 或训练。

## 解决方式：不改名冒充兼容，建立新版本

问题不是把一个字段名改掉就结束。旧链路把运行后观察到的 `h_patterns/m_patterns` 填入名为 limit 的特征；现在要推荐尚未执行的动作，只能使用提前知道的请求限额。没有证据证明两者恒等，也没有认证真实 checkpoint 的特征版本。

本轮选择并实现 **`REQUESTED_COUNT_V1`**：新向量只使用请求值，实际产出进入独立观察记录，旧模型和历史数据不改。旧 schema 或未知 schema 在新接口会被拒绝；新 schema-ID 匹配也只表示字符串标识一致，绝不是权重、图、checkpoint 或推理许可已认证。

**已解决的是代码层的输入语义与连接问题，不是已经证明旧权重可用，也不是已经完成新模型训练。** 如果后续不能取得旧输入等价性证据，应采用带真实请求谱系的数据和新模型版本，而不是把旧实测数量重新标成请求。

## 已实现的两部分

### 1. 运行前特征

`src/data/prospective_request_features_v1.py` 冻结调用方提供的完整请求清单、最大 H/M 请求值、共同故障数、图摘要与特征 schema。七个新列的 H/M 名称明确带 request，不包含实际 pattern 数、F 结果、cycles、覆盖率或 runtime。

例如清单中最大 H 请求为 8，而当前候选请求 4，则比例一直为 4/8=0.5。只选这一条做排序时也不会变成 4/4=1。子集不能重新计算分母；改变清单、图、共同故障数、字段类型或冻结内容，都会改变身份或被拒绝。

HF 的 M=0 仅是“没有 M 阶段”的数值哨兵，不是观察到了一次 M=0 的执行。冻结 SHA 也不证明调用方没有隐瞒候选或图摘要对应真实图；真实使用仍须与外部预注册全清单核对。

### 2. 运行后观察

`src/data/prospective_stage_observation_v1.py` 按 run/action/attempt/stage/index、请求哈希和前缀身份连接结果。不会用“两个数字碰巧相等”来连接。

具体例子：请求 H 上限为 4，而报告生成 2。新记录同时保留请求 4、产出 2，并标记这次观察不相等；它不把请求改成 2，更不把 2 填入新请求特征。即使改动后续 F 的产出、cycles 或检测数，冻结特征摘要也保持不变。

条件阶段有明确谱系：HF 为 H→F，HMF 为 H→M→F。M 必须绑定成功 H 的 attempt 和结果 SHA；F 绑定对应成功前缀，每次探测按本版保守规则重建新前缀。旧 M、其他 action 的前缀、重复物理身份、错配请求哈希、非法顺序均拒绝。F 控制明确区分 pattern limit、full 和十进制字符串覆盖率目标，没有暗中漏掉请求模式。

已知失败会保留并计入调用方断言的区间，可继续另一个独立 action，但不能自动重试同 action。缺失耗时、未知退出或未确认终止，会让区间总和为空并阻止后续观察。这里验证的是传入记录：没有启动进程、没有认证操作系统，也没有把这些区间转成可训练的真实 ATPG 标签。

进程成功也不等于 D95 安全。代码可比较“声明分母下是否达到阈值”，但固定输出 `acceptance_authenticated=false`，不把调用方报告摘要当故障映射或安全准入证明。解析器最多 64 对记录的限制不是批准的真实 attempt 预算。

## 已验证的工程场景

- 请求与产出不同仍能准确连接，并且特征不被结果改写。
- 全清单归一化在选择子集后保持不变。
- 旧/未知 checkpoint schema 被拒绝，新 ID 匹配不放行推理。
- 合法 HMF 两轮前缀重建/F 探测可以连接；复用旧前缀和旧 M 会被拒绝。
- 错 action/attempt/hash、重复进程、host/boot 漂移、结果字段混入请求均被拒绝。
- 成功但缺耗时/终止确认时仍返回不完整，不补零或 timeout。
- 冻结结构中的 `False→0`、`0→False`、整数→等值浮点数也被规范化哈希检查拒绝，不利用 Python 的宽松相等比较。

所有演示数据都是构造值：common count=100、图摘要为占位、计时是人为整数，没有实际实验意义。最终两次小结果各 12,361 B，逐字节一致，SHA-256 `fae571451f56988fe359035fadadd93804eaccc982ffbce578b5e96a3e862a09`。早期 r1 演示保留在 staging，记录为规范化类型修复前的中间证据，不作为最终版本。

最终 18 项针对性测试通过（7 项新特征、11 项观察连接；0.010 秒，零失败/错误/跳过）；独立复核另运行同组 18 项通过，0.010 秒。相关完整回归 1,156 项中 1,150 项执行通过、6 项条件跳过，零失败/错误，73.539 秒。旧回归中的微型本地 Python 子进程仍是旧测试，不是新的 ATPG、SSH 或训练。独立审核还核对两次演示与 Git 小结果的字节、6 个来源 SHA、字段分离、父前缀谱系与未放行边界。
